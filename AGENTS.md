# This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.

# HabitForge Project Rules

## Database (Prisma v7)
- Prisma v7 requires a driver adapter (`@prisma/adapter-pg`). No `datasourceUrl` option.
- `PrismaClient` constructor requires `{ adapter }` option.
- Never import `@/lib/prisma` in client components — it bundles `pg` which fails.
- Use `getPrisma()` or `await import("@/lib/prisma")` only in API routes and server-only code.

## Auth (NextAuth v5 / Auth.js)
- `AUTH_SECRET` must be set in `.env.local` or the app crashes at runtime.
- Use `next-auth` v5 beta (`next-auth@beta`).
- Auth middleware uses `src/proxy.ts` (Next.js 16 convention), NOT `src/middleware.ts`.

## Build Notes
- Build requires `DATABASE_URL` set in `.env.local` because PrismaAdapter is evaluated at build time.
- HTML build errors from recharts can be ignored (charts render client-side).
- Remove `vitest.config.ts` before build if vitest isn't installed.

## Client-Server Boundary
- Client components cannot import anything that transitively imports `@prisma/client` or `pg`.
- The `@/lib/ai.ts` module uses `await import("@/lib/prisma")` — still not safe for client imports.
- Use `@/lib/ai-client.ts` for client-safe AI functions (just `getDailyQuote`).
- Client components call `/api/ai/*` endpoints for AI features instead of importing `@/lib/ai`.

## Deployment
- Vercel: Set all env vars in project dashboard. `DATABASE_URL` is required.
- Docker: `docker compose up -d --build` starts app + PostgreSQL + Redis.
- Run `npx tsx scripts/seed.ts` after first migration.
- PWA manifest and service worker are auto-generated by vite-pwa or next-pwa.
